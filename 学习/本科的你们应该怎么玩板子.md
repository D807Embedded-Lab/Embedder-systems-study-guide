# 本科生应该怎么玩板子

## 一、先不急着买板子，想想这次准备玩什么

本科阶段接触开发板，其实不一定要按照一条固定路线，从 STM32 入门，再学 ESP32，最后学 Linux。不同的板卡有不同的特点，完全可以根据自己感兴趣的东西，选择一块板子，围绕它做一个小项目。
比如，你想研究 DMA，可以找一块 DMA 功能比较丰富、资料齐全的 MCU 板；想玩电机控制，可以看看 TI C2000；想了解 FPGA，就试试高云的 Tang Nano；想做 ROS 2，就需要考虑能够运行 Linux 的计算平台。
这些板卡之间没有必要排出一个绝对的高低顺序。你可以从自己熟悉的领域往外拓展，也可以因为某个新功能，直接接触一个之前没用过的厂商。
所以这篇不准备给大家规定一份必须购买的清单，而是把不同板卡的特点、可以玩的内容，以及怎么把它们放进项目里，放在一起聊一聊。
下面的价格均为大致预算，具体会随版本、配件和渠道变化。有些板卡适合个人购买

## 二、先从便宜的板子开始，玩法其实可以很多

### 1. Arduino UNO R3：快速验证一个想法

Arduino UNO R3 适合用来做一些小型实验。它的优势是外围模块丰富、接线简单，可以很快把一个想法变成实际运行的东西。
比如，想研究光照传感器如何控制灯光，就可以接上光敏电阻和 LED；想做一个简单的自动门，就可以增加超声波传感器和舵机。
它不一定要承担很复杂的底层开发任务，也可以作为验证想法的工具。先把功能跑通，再考虑怎么把程序移植到其他 MCU 上，或者自己实现其中的驱动。

### 2. WCH CH32V003：用很低的成本研究 RISC-V MCU

如果觉得 Arduino 封装得比较多，可以看看沁恒的 CH32V003。
这是一款基于 RISC-V 内核的低成本 MCU。它的资源比较有限，反而适合拿来研究一些基础问题。
例如：

- 不依赖大型框架，直接配置 GPIO 和定时器。
- 看程序启动后如何进入主函数。
- 使用中断处理按键和定时事件。
- 研究串口收发、简单状态机和内存占用。
- 比较不同开发环境生成的程序，以及编译后代码的大小。

可以做一个小型传感器节点，只有一个 MCU、一个传感器和一个通信接口。把程序尽可能做小，再观察功能增加以后，Flash 和 RAM 分别增加了多少。
这块板不适合用来承担大型项目，但很适合用来研究资源有限的 MCU 应该怎么设计程序。

### 3. Raspberry Pi Pico 2：试试 DMA、PIO 和双核

Pico 2 使用 RP2350，可以选择双 Cortex-M33 或双 RISC-V Hazard3 内核配置，适合进一步研究 MCU 的底层机制。
它比较值得玩的地方，不只是 GPIO，而是 DMA、PIO 和双核。
例如，可以做一个简单的数据采集系统：定时器触发采样，DMA 把数据搬运到内存，CPU 再对数据进行处理。
完成以后，可以继续改：

- 将轮询改成中断，比较两种实现的差别。
- 将 CPU 逐次搬运改成 DMA，观察 CPU 占用情况。
- 使用循环缓冲区，研究数据生产速度和消费速度不匹配时会发生什么。
- 尝试让两个核心分别承担采集和数据处理任务。

同样是读取一组数据，通过不同的实现方式，就可以研究中断、DMA、缓冲区和多核协作。

### 4. ESP32-C3：把一个小项目连接到网络

ESP32-C3 适合拿来玩 Wi-Fi、BLE 和简单物联网应用。
例如，做一个无线温湿度节点，把采集到的数据发送给电脑；也可以做一个手机控制的继电器节点，研究设备配网、断线重连和远程控制。
如果只是调用现成的 Wi-Fi 接口，项目很快就能跑起来。接下来可以进一步研究 MQTT、TCP/UDP、网络连接状态机，以及通信异常后程序如何恢复。
同一块板可以有很多种玩法。区别主要在于，你是满足于功能跑通，还是准备继续研究功能背后的实现过程。

## 三、不要只盯着 STM32，可以换几家厂商试试

当大家已经有一定的 MCU 基础以后，我觉得可以有意识地换一换开发平台。
不是说一定要放弃 STM32，而是找一些特点不一样的芯片。比如，有的更适合低功耗，有的外设比较丰富，有的适合研究电机控制，还有的提供了不同的开发工具和软件生态。

### 1. STM32 NUCLEO-F401RE：把底层驱动真正研究一遍

NUCLEO-F401RE 使用 Cortex-M4 内核，板载 ST-LINK，适合研究 STM32 的启动、外设和调试流程。
如果已经做过几个基础项目，可以选一个自己比较熟悉的功能，例如 UART 数据接收，然后尝试不依赖完整的现成例程，从时钟配置、引脚复用、外设寄存器一直研究到数据接收和错误处理。
还可以继续把轮询、中断和 DMA 三种方式放在一起比较，观察不同实现方式对 CPU 占用、数据丢失和响应时间的影响。
这里推荐的不是某个固定项目，而是一种玩法：**选一个自己已经会用的外设，再往下研究它究竟是怎么工作的。**

### 2. 兆易创新 GD32：换一个 MCU 生态，看看同样的功能怎么实现

兆易创新的 GD32 系列提供了多种不同定位的 MCU，既有适合入门的型号，也有集成更多外设的高性能型号。
可以选一块 GD32F303 或 GD32F4 系列开发板，把之前在 STM32 上做过的项目移植过来。
移植时，不要只关注程序能不能编译通过。还可以比较时钟配置、外设初始化、驱动库、编译器设置和调试方式的区别。
如果原来的项目采用了比较清晰的驱动层和应用层设计，就可以进一步观察哪些模块可以直接复用，哪些地方需要针对新平台修改。
GD32 的价值不在于把原来用 STM32 做的项目重新做一遍，而是借助同类 MCU 的对比，理解硬件抽象和代码移植。

### 3. Renesas RA4M1：试试瑞萨的开发工具链

瑞萨的 RA 系列也是一个可以接触的方向。
例如，EK-RA4M1 采用 Cortex-M4 内核，提供板载调试器、扩展接口和相关开发工具，适合研究瑞萨的 FSP 软件包与外设驱动。
可以尝试做一个带触摸输入的小型交互设备，研究 GPIO、定时器、串口和触摸接口等功能。
也可以把之前写过的一个驱动模块移植到 RA 平台，再比较两种开发环境下的工程组织和外设配置。
官方资料：[Renesas EK-RA4M1](https://www.renesas.com/en/design-resources/boards-kits/ek-ra4m1)。

### 4. NXP FRDM-MCXA153：看看另一种 MCU 的开发方式

NXP 的 MCX 系列可以作为另一个拓展方向。FRDM-MCXA153 适合接触 MCUXpresso 工具链、Cortex-M33 和相关外设开发。
可以拿它做一个简单的执行器控制节点，再尝试把应用层与底层驱动分开。
如果已经熟悉 STM32，也可以把一个小型项目移植过来，比较不同厂商的外设驱动和开发环境。
这样一来，接触新板卡就不只是重新学习一套函数，而是有一个可以对照的参照物。

## 四、如果不想一直研究普通 MCU，可以玩一些更有特点的平台

前面介绍的板卡，大部分还是以通用 MCU 为主。接下来就可以按照兴趣，去接触一些用途更加明确的开发平台。
这里不必每个方向都学，可以挑自己觉得有意思的先试试。

### 1. TI C2000：从控制程序走向实时控制算法

如果想玩电机控制、数字电源或者实时信号处理，可以看看 TI C2000 系列。
例如 LAUNCHXL-F280049C，提供 C28x 实时控制内核、浮点运算能力、ADC、PWM 和相关控制外设。
它比较适合研究采样与控制输出之间的时序关系。
可以先做一个电机转速闭环控制项目，再逐步加入数字滤波、PID 调节和异常保护。过程中可以用示波器观察 PWM 波形和采样时序，分析控制周期是否满足要求。
还可以进一步研究 ADC 与 PWM 同步、控制算法执行时间，以及不同滤波方法对控制效果的影响。
TI 官方资料：[LAUNCHXL-F280049C](https://www.ti.com/tool/LAUNCHXL-F280049C)。
如果准备进入电机控制、新能源或者数字电源方向，这类平台就很有价值。

### 2. Microchip dsPIC33：试试另一条数字控制路线

Microchip 的 dsPIC33 系列也值得了解，尤其是数字电源、电机控制和实时信号处理方向。
可以选择对应的 Curiosity 开发板，研究 PWM、ADC、数字滤波以及控制算法的实现。
与普通 MCU 项目相比，这里的重点是让采样、运算和控制输出按照要求的时间完成。
如果已经做过 TI C2000 项目，也可以尝试在 dsPIC33 上实现同一个简化控制算法，比较开发工具、外设配置和代码实现方式。
这类对比并不是为了得出哪家厂商更好，而是了解不同平台在同一类问题上的设计思路。

### 3. Nordic 或 Silicon Labs：玩低功耗无线通信

如果对无线通信感兴趣，可以看看 Nordic 的 nRF52 系列，或者 Silicon Labs 的 EFR32 系列。
这两家都有面向 BLE 等无线应用的开发平台，部分型号还支持 Thread、Zigbee 等相关协议。
可以做一个低功耗无线传感器节点，研究设备如何配网、如何传输数据，以及设备在空闲时怎样降低功耗。
还可以把两个节点放在不同距离，记录 RSSI、丢包率和通信恢复时间，比较不同环境下的通信质量。
Nordic 适合了解 BLE 等无线应用开发；Silicon Labs 的相关平台也适合接触低功耗无线和多协议物联网应用。具体支持哪些协议，要以选定的芯片型号和软件栈为准。
如果只是做普通 Wi-Fi 物联网，ESP32 已经够用；如果想进一步研究低功耗无线网络，这类平台就有了不同的价值。

### 4. 高云 Tang Nano 9K：不再只写软件，试试自己设计硬件逻辑

如果想换一种思路，可以试试高云 FPGA 配合 Sipeed Tang Nano 9K。
它适合学习 Verilog、数字逻辑、状态机、时序约束，以及 FPGA 的综合和验证流程。板卡还提供 HDMI 等接口，可以用来做简单的视频输出或数字逻辑实验。
可以从一个 UART 接收模块开始，自己设计状态机，再做一个简单的 SPI 控制器，最后尝试把多个模块组合起来。
如果想继续拓展，可以试着实现并行数据处理，或者在 FPGA 上验证一个简单的 RISC-V 软核。
这里的思路和 MCU 不太一样：MCU 是运行软件去控制硬件，FPGA 则可以让你自己描述和组合数字逻辑。
官方资料：[高云 Tang Nano 9K](https://www.gowinsemi.com/en/support/devkits_detail/43/)。
这类板卡价格相对可控，适合对数字电路、硬件加速或者 FPGA 感兴趣的同学。

### 5. NXP i.MX RT1060：研究高性能 MCU 与外部存储

NXP i.MX RT1060 是一个适合继续研究高性能 MCU 的平台。它采用 Cortex-M7 内核，评估板提供外部 SDRAM、Flash、SD 卡接口、LCD、摄像头和以太网等资源。
它很适合用来研究一个普通入门板不太容易展开的内容：外部存储和高速外设之间如何协同工作。
例如，可以尝试做一个图像采集与显示项目，研究图像缓冲区放在哪里、DMA 如何搬运数据、屏幕刷新会占用多少带宽，以及外部 RAM 的访问会对性能产生什么影响。
也可以进一步接触 FreeRTOS、Zephyr 等系统环境。
这块板的价格不算低，不建议单纯为了学习某一个外设而购买。如果实验室有类似平台，可以先用现有设备完成相关实验。

## 五、如果想玩 Linux、AI 和机器人，可以从计算平台入手

这一类项目往往需要比普通 MCU 更大的内存、更完整的操作系统，以及更强的计算能力。
不过，具体选什么平台，还是要看你准备做什么。

### 1. Raspberry Pi 4 / Raspberry Pi 5：Linux 与 ROS 2

<text color="secondary" size="sm">参考价格：约 300～700 元，视型号、内存和配件而定</text>

如果想接触 Linux、网络服务或者 ROS 2，可以从树莓派开始。
可以学习进程、线程、Socket、设备树和 Linux 驱动，再逐步进入 ROS 2 的节点、话题、服务和传感器数据处理。
例如，做一个简单的移动机器人：树莓派负责运行 ROS 2，STM32 负责电机控制和编码器采集，两者通过串口或 CAN 交换数据。
后续还可以接入摄像头、激光雷达，研究传感器数据同步、导航和控制指令的延迟。
如果只是做 ROS 2 入门，没必要一开始就购买昂贵的机器人平台。先把 Linux、ROS 2 和 MCU 之间的通信跑通，就已经可以开展不少实验。

### 2. Orange Pi 5 Plus：Linux、NPU 与边缘 AI

<text color="secondary" size="sm">参考价格：约 500～1,000 元以上，取决于内存与存储配置</text>

如果想进一步研究 Linux 下的视觉处理和边缘 AI，可以看看 Orange Pi 5 Plus。
它使用 Rockchip RK3588，提供多核 CPU、GPU 和 NPU，适合接触 Linux、图像处理和端侧模型部署。
例如，可以做一个摄像头目标检测项目，研究摄像头输入、图像预处理、模型推理和结果输出之间的完整流程。
后续还可以比较不同输入分辨率、模型大小和推理框架下的延迟与内存占用。
但这里需要注意，NPU 的算力参数并不等于项目的实际推理速度。模型是否支持、驱动和推理框架是否适配，都会影响最终效果。
如果只是学习 Linux 和 ROS 2，可以先用树莓派；如果准备深入视觉和端侧 AI，再考虑 RK3588 这类平台。

### 3. NVIDIA Jetson：把机器人和 AI 结合起来

如果想做视觉机器人、目标检测、深度学习推理，可以进一步了解 NVIDIA Jetson 系列。
它的优势是能够利用 NVIDIA 的 GPU 计算和软件生态，适合研究机器人视觉、模型部署以及 ROS 2 与 AI 的结合。
可以做一个基于摄像头的目标检测机器人：Jetson 负责图像处理和识别，MCU 负责电机控制和底层传感器采集。
这样可以把视觉计算与实时控制拆开，分别研究两边的性能和通信问题。
不过，Jetson 的预算和功耗通常比入门 MCU 高不少。如果实验室已有设备，优先借用更合适。没有明确的视觉或 AI 需求时，也不需要为了学习嵌入式而购买。

## 六、如果准备往汽车电子发展，可以再接触 AUTOSAR 相关平台

### 1. NXP S32K144

<text color="secondary" size="sm">参考价格：约 650～850 元，具体以渠道为准</text>

S32K144 是面向汽车电子应用的 MCU 平台，可以用来学习 CAN、LIN、底层驱动和 ECU 软件设计。
可以先做一个简单的车身控制器，实现灯光控制、传感器采集、CAN 通信和故障状态管理。
之后再研究 AUTOSAR Classic 的软件分层，包括应用软件、RTE、BSW 和 MCAL。
需要注意，开发板并不等于完整的 AUTOSAR 开发环境。实际进行配置与集成，还需要对应的软件栈、工具链和授权条件。

### 2. Infineon AURIX TC375 Lite Kit

<text color="secondary" size="sm">参考价格：视渠道而定，通常更适合实验室共享</text>

如果想进一步研究汽车实时控制、多核架构和功能安全，可以了解 AURIX TC3xx 系列。
它适合用来研究多核任务分配、核间通信、共享资源同步、实时调度和故障处理。
例如，可以将采集、通信和控制任务分配到不同核心，记录执行时间和核间通信延迟。
如果后面想深入 AUTOSAR 或汽车实时系统，这类平台值得接触。但在预算有限的情况下，先从普通 MCU、CAN 通信和底层驱动入手，再利用实验室设备开展专项学习，会更合适。

## 七、一个项目究竟应该怎么挑选板卡？

前面介绍了很多板卡，但真正做项目时，往往不是先决定买哪块板，再想它能做什么，而是先明确项目需要解决什么问题。
我一般会先看下面几个方面。

**第一，项目最核心的任务是什么？**

如果主要是周期采样、电机控制和执行器控制，那么优先考虑 MCU；如果需要运行 Linux、处理复杂网络服务或运行 ROS 2，就需要应用处理器平台；如果涉及高速数字逻辑或特定并行处理需求，可以考虑 FPGA。

**第二，项目需要哪些接口和硬件资源？**

例如，电机控制项目需要关注 PWM、ADC、编码器接口和保护机制；摄像头项目需要关注摄像头接口、内存带宽和图像处理能力；无线节点则需要关注通信协议、功耗和天线设计。

**第三，软件环境能不能支撑项目？**

有些芯片硬件资源很丰富，但驱动、SDK 或相关软件栈的支持可能不符合项目需要。尤其是 ROS 2、AI 和 AUTOSAR 这类方向，软件环境往往和硬件同样重要。

**第四，实际成本是多少？**

不能只看开发板本身的价格。还要考虑下载器、扩展模块、电源、存储卡、调试仪器，以及必要的软件授权和配件。
对于学生项目，优先选择资料完整、调试方便、能够获得支持的平台，往往比选择参数最高的板卡更省时间。
下面举几个实际例子。

| 项目需求 | 可以考虑的平台 | 主要考虑因素 |
|---|---|---|
| 低功耗智能家居节点 | ESP32-C3、Nordic nRF52、Silicon Labs EFR32 | 无线协议、功耗、开发生态 |
| 电机控制与数字电源 | STM32G4、TI C2000、Microchip dsPIC33 | ADC/PWM 配合、控制周期、保护机制 |
| 高速数据采集 | STM32H7、NXP i.MX RT1060 | DMA、缓存、外部 RAM、带宽 |
| Linux 网关与 ROS 2 | Raspberry Pi、Orange Pi | 系统支持、内存、接口和软件生态 |
| 视觉与端侧 AI | Orange Pi RK3588、NVIDIA Jetson | 模型支持、推理速度、功耗和内存 |
| 数字逻辑与硬件加速 | Gowin Tang Nano、AMD/Xilinx FPGA | 逻辑资源、接口、开发工具和时序 |
| 汽车 ECU 与 AUTOSAR | NXP S32K、Infineon AURIX | 软件栈、工具链、通信与实时性 |

如果一个项目同时涉及多种任务，也不一定需要一块板全部完成。
例如，移动机器人可以使用 STM32 处理底层控制，树莓派运行 ROS 2；智能家居可以使用多个 ESP32 节点，再用 Linux 网关负责数据管理。
这里的关键是明确每块板的职责，以及板与板之间通过什么接口交换数据。

## 八、拿到一块新板卡以后，具体应该怎么玩？

这一部分我觉得比记住板卡型号更重要。
因为真正接触新板卡时，大家经常遇到的问题不是没有例程，而是不知道除了运行例程，还能继续研究什么。
我建议可以按照下面的思路开展一次板卡实验。

### 1. 先把硬件资料看明白

不要一上来就复制代码。先看芯片型号、核心架构、Flash、RAM、外设、引脚复用和供电要求。
如果有原理图，再看看板载调试器、时钟源、存储器、通信接口和扩展引脚分别连接在哪里。
不需要一次性把所有内容全部看完，先找出本次实验真正会用到的部分就可以。

### 2. 把最小工程搭起来

先确认开发环境、编译器、下载工具和调试接口都正常。
然后编译一个最小工程，完成下载、断点调试和串口输出。接下来可以试着从启动文件、主函数、时钟配置和外设初始化一路跟下去。
这样以后遇到编译失败、程序跑飞或者外设没有响应时，就有一些可以检查的入口。

### 3. 不要只运行例程，试着修改它

假设官方提供了一个 DMA 示例，不要只看它能不能运行。
可以尝试改变缓冲区大小、传输长度和触发方式，观察程序行为；再将 DMA 改成中断或轮询，比较 CPU 占用和数据处理延迟。
如果是双核平台，可以尝试让两个核心分别处理不同任务，再研究共享数据时会遇到什么问题。
如果是 FPGA，可以修改状态机和时序；如果是 DSP，可以修改滤波器或控制算法；如果是 Linux 板卡，可以修改驱动参数或者增加一个用户态服务。
不同板卡有不同的研究入口，不需要把所有板卡都玩成同一种项目。

### 4. 找一个能体现板卡特点的小项目

每块板不一定都要做完整的大项目。
例如：

- 用 CH32V003 研究小内存条件下的程序设计。
- 用 Pico 2 研究 DMA 和 PIO。
- 用 STM32H7 研究缓存与 DMA 的配合。
- 用 TI C2000 研究电机控制的采样和输出时序。
- 用 Tang Nano 9K 研究 FPGA 状态机和并行逻辑。
- 用 Nordic 或 Silicon Labs 平台研究低功耗无线通信。
- 用树莓派研究 Linux、ROS 2 和设备驱动。

每个项目只要能够验证一个具体问题，就可以成为一次有效的实验。

### 5. 尝试把同一个功能移植到另一块板上

这是我比较推荐的一种玩法。
例如，先在 STM32 上实现一个 UART 数据接收模块，再移植到 GD32 或 NXP 平台；先在一块 MCU 上完成简单的数字滤波，再移植到 TI C2000。
移植时，你会逐渐发现，有些代码与硬件无关，有些代码依赖具体的外设和驱动，有些差异来自编译器、内存布局或开发框架。
这些问题很适合进一步研究，也可以慢慢积累成自己的开发笔记。

## 九、最后，板卡可以多接触，购买不一定要多

个人购买时，可以先选择两三块低成本平台，再根据项目需求增加专项设备。像 FPGA、DSP、无线通信、Linux 和汽车 MCU 这些方向，都可以先做一次小实验，看看自己是否感兴趣，再决定要不要继续深入。
板卡的玩法其实没有必要完全固定。同一块板，可以研究外设，也可以研究内存；可以做通信，也可以做实时控制。不同厂商的板卡之间，还可以通过移植和对比，发现各自的特点。
我更希望大家接触新板卡时，先看它有什么特别之处，再找一个合适的问题去验证。这样每换一块板，就能多接触一种实现思路，而不是把同一套例程在不同开发板上重新运行一遍。
本科阶段不需要把所有平台都学完。多接触一些不同的硬件，知道它们分别适合做什么，再围绕自己感兴趣的方向继续往下研究，就已经能打开很多新的思路了。
