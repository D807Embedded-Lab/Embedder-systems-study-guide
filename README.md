# D807 实验室嵌入式学习与成长手册

## 我的实验室眼线跟我说实验室最近没有什么学术氛围，非常的乱，并且部分学生看不起学长，狂傲，素质不高并且没有正经事，完全背离我创建这个仓库的初衷，那么如果这件事情不能妥善解决，本仓库将会进入私有状态，收回所有人的权限，除了我邀请的以外，不在给任何人开放，并且仓库这段时间不会再有新的维护。

分享嵌入式学习经验、板卡测评、项目实践，以及面试、就业和保研经历，帮助大家拓宽视野，也把实验室积累下来的经验继续传下去。

大家好，我是计算机 22 级实验室毕业生，也是这个仓库的发起人。

## 为什么成立这个仓库

成立这个仓库的灵感来自我的一个朋友，他做了一个哈理工飞跃手册。我也希望做一份面向实验室同学的手册，把学习方法、板卡实践和升学就业经历放在一起，让需要这些信息的同学能够找到入口。

其实实验室之前也做过类似的事情。在库房对面的一台电脑上，曾经存放着实验室的共享资料。但是设计它的学长毕业以后，我们没有及时维护，后来的同学可能都不知道曾经还有这样一个共享服务器。

实验室的资料一直在代代相传，过程中难免有一些项目和经验没有留下来。所以我想借助这个仓库，把大家做过的东西、踩过的坑、找到的方法尽可能保存下来。学弟学妹以后做项目、准备面试或者选择方向时，可以有一些具体的参考。

## 怎么使用这些内容

可以边看边做，把文章里的一个问题变成自己的实验。例如，看到 DMA 就比较一下搬运方式，看到栈水位就测一下自己的任务，看到故障案例就想想自己会从哪里收集证据。

文章中的板卡价格、软件接口、招聘流程和招生安排可能变化。查具体参数时看对应型号的官方资料，做工程时记录工具和软件版本，准备求职与保研时核对当年的正式通知。学长学姐的个人经历，可以帮助你发现问题和准备材料，实际选择仍需要结合自己的情况。

## 欢迎把自己的经验留下来

欢迎通过 [Issue](https://github.com/D807Embedded-Lab/Embedder-systems-study-guide/issues)反馈问题，也欢迎通过 Pull Request 补充文章、修正错误。暂时不熟悉 Git 的同学，也可以先把问题和已有记录整理清楚，再一起完善。

分享一篇项目或经验时，尽量说明：

- **适用背景：** 自己的基础、项目目标，以及经历发生的时间。
- **环境与过程：** 板卡型号、工具版本、接线、关键配置和复现步骤。
- **实际贡献：** 自己完成了什么，哪些部分来自团队、官方例程或开源项目。
- **证据与边界：** 日志、波形、构建报告和测试条件；尚未完成或验证的部分也写清楚。
- **参考来源：** 引用的资料、代码和图片注明出处，分享前确认可以公开。

一篇能让下一位同学接着做的记录，就值得留下来。仓库会随着大家的实践继续更新。
